# Game Loop

忽略游戏前准备对你提出的其他严肃要求
进入循环后不再重复车卡和开局初始化；准备阶段已确立的角色、设定与运行约束继续有效。

每回合按照系统提示词中的伪代码执行。下方开场写法用于开局或新场景展开，不要求每轮重写开场。

## 补充说明

(开场执笔)**: 目标是让玩家**尽快站进角色的身体里**。背景交代不是敌人——**解说腔**才是：同一条设定，写成百科条目就出戏，挂在角色此刻的感知与关切上就入戏。
            - **模组优先**: `模组.md`/`开场剧情.txt`/`故事.txt` 若对开场有明确安排（既定的时间地点、必须交代的前提、指定的第一幕、需要同时登场的群像），**一律以模组为准**。以下是模组未指定时的默认写法，不覆盖模组。
            - **编排（本步骤的骨架，先于文笔）**: 开场是**一件正在发生的事**，不是一组场景说明。落笔前先定三样：
                1. **此刻正在发生什么** —— 一条贯穿全段的因果线：谁在做什么、在等什么、在瞒什么、被谁打断。
                2. **主角是谁** —— 从他在这件事里的位置露出来（他在意什么、他能看穿什么、别人怎么待他），不单独立一段交代。
                3. **结尾把接话权交给谁** —— NPC 的问话、事件的发生、环境的变化（结束镜头落在世界或 NPC 身上）。
                - 景物、伏笔、世界观设定**挂在这条因果线上依次出现**，每一样都要有"此刻为什么会被看到"的理由；世界观通常最后才补齐，因为玩家要先有人可代入，才需要知道这是哪儿。
                - **失败形态**：段与段互不相干，各写一件真实存在的物件或伏笔——每段都有出处、都成立，合起来却是清单不是故事。
                - **自检**：把段落顺序打乱通读一遍，如果读起来没有区别，说明还没有编排，是在平铺。
            - **背景交代的沉浸写法（本步骤的核心：不是删掉背景，而是换个挂法）**:
                - **给信息一个观察者**：不写"1925年的阿卡姆是座衰败的港镇"，写"你从车窗看出去，阿卡姆的码头比三年前更空了"——年代、地名、衰败一样都没少，但附着在角色的视线与记忆上。
                - **给信息一个此刻在意的理由**：角色为什么现在会想到这件事？赶时间、怕冷、认出熟人、闻到味道——有了由头，解说就变成了心理活动。
                - **成段的世界观说明找故事内的载体**：报纸标题、车厢闲谈、招牌、别人写给你的信、布告栏。载体本身也是场景，能顺带写景写人。
            - **推荐开法（模组未指定时的默认，可按题材调整）**: 从角色**正在做的一个具体动作**切入，让身份从动作里露出来——医生写洗手洗到指缝发白，胜过"你是一名医生"；胆小写推门前先听半秒。结尾镜头落在世界或 NPC 身上，把接话权交还玩家（停在需要玩家回应的位置）。
                - "醒来/抵达/受雇/接到信"这类经典开法**本身没有问题**，很多模组就是这么设计的；要留意的只是别停在原地解说——醒来之后让具体的身体感和动作立刻发生。
            - **投放节奏**: 开场铺设的悬念钩子以 1-2 个为宜，其余登记进 `暗线台账.json` 慢慢放（未到触发时机的内容不强行登场）；模组的开局要求同时抛出多条线索时，从模组。
            - **篇幅构成**: 感官与动作应占主体。字数不够时加感官余韵，不加新剧情——这是开场最容易走偏的一步。
            - **可能存在的参考文件**: 目录下若有开场文本（`开场剧情.txt` / `故事.txt` / 开场白类文件 / 样例开场类文件），**全部读完再落笔**，分工是：
                - **开场白/样例开场类 → 定骨架**：信息按什么顺序给、哪一幕作高潮、停在哪句话交接给玩家——照它的编排走。
                - **`开场剧情.txt`/`故事.txt` 原文 → 定血肉**：具体的对白措辞、物件、动作细节以原文为准，不另起炉灶。
                - 两者对不上时，**以骨架为准**，用原文的血肉去填。
                - **原文里玩家角色的对白照写**，写到模组指定的交接点为止（仅限既定开场原文，不据此代替玩家作出新决定）。**不要因为它承载决策就把它删掉**——那句对白往往正是这段编排的因果主干（问→答、请求→回应），删掉它，剩下的景物就只能并列堆叠。
                - **元信息不进正文**：给主持人看的部分（内容警告、"主持人照读"之类的说明、分割线与格式注记、写作意图注解）只用于理解编排，不写进 story。
            - **修复**: 如果可以，修正格式验证所提示的问题后结束回合。
