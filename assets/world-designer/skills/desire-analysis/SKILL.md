# 欲望分析

人表述的从来不是欲望本身，而是欲望经过一次有损压缩后的残骸。压缩掉的部分对他自己不可见——他脑内有完整的背景、动机和默认前提，看自己的表述时这些会自动补全，所以他确信自己说清楚了。

这带来一个固定后果：**照着表述做，做出来的东西他不满意，但他也说不出哪里不对。**

常见形态：

- 提了一个方案，实际想解决的是另一个问题
- 写了一段自己很满意的东西，别人读了无感
- 反复说「差点意思」，但给不出具体的差在哪
- 两人争执的是方案，真正冲突的是各自没说出口的约束

## 方法根基

不要问「你为什么想要这个」。人对自身偏好的内省报告不可靠，问出来的多是事后合理化——听起来有条理，但不是真实动因。

**人对具体选项的取舍反应是可靠的。** 所以整个流程只让对方做二元判断，从判断的模式里倒推。

## 适用边界

输入：一份表述（方案、片段、需求、抱怨），且有迹象表明它与真实意图不一致。
输出：需求清单——必需项、可弃项、以及成立所需的前提条件。
不做：不产出成品、不给实现方案。挖出的结论交给对应的执行流程。

表述本身已经清晰、或代价低到试错更快时，不要进入本流程——它要十几轮往返。

## 流程

### 一、定位落点

不问「你为什么要这个」，问「**这件事做成之后，最终该是什么状态**」。

落点是可描述的状态，不是因果解释。对方答得出「省心」「不再被追问」「看着就服气」这类词。

问的时候把落点放在**承受结果的那一方**身上，而不是对方自己身上。问「你想做出什么」，他会答一个方案（「我想写出一章爽文」「我想做个好用的后台」）——那是他已经给过的表述，绕回原地了。要问的是结果落到别人身上是什么样：读的人心里剩下什么、用的人不用再做什么、听的人会怎么改口。谁承受结果，就从谁身上问。

答案里出现矛盾组合时（「要快但要稳」「要爽但要有点酸」）尤其有价值——说明诉求不止一个，后面要分开剥。

### 二、剥离测试

拿他给的原始方案，**一次只改一个要素**，问「这样还是你要的吗」。

对方答「还是」或「不是了」。**答「不是了」的那一刀，砍中的就是核心。**

通用剥离轴：

| 轴 | 改法 | 测什么 |
|---|---|---|
| 主体 | 换一个人来做／换一个对象承受 | 特定主体是否必需 |
| 难度 | 轻松达成改成艰难达成 | 「不费力」是否必需 |
| 见证 | 公开改成无人知晓 | 「被看见」是否必需 |
| 归属 | 结果一样但功劳不归他 | 「记在我头上」是否必需 |
| 代价 | 无损改成付出明显代价 | 「零成本」是否必需 |
| 时机 | 立刻发生改成很久之后 | 即时性是否必需 |
| 完整度 | 全部满足改成满足八成 | 是否有不可让步的部分 |
| 可逆性 | 一次性改成随时可改 | 「能反悔」是否必需 |

三到五刀即可画出边界。连续两次答「还是」，说明核心已裸露，停手。

一刀只动一个变量——同时改两处，对方说「不是了」你无法归因。

示范。对方要的是「每周一自动发一封数据周报给全组」：

> — 改成有人问的时候你一键生成给他，还是你要的吗？
> — 不是了，那还是得我经手。
> — 改成周报照发，但发件人是系统不是你，还是你要的吗？
> — 还是。
> — 改成不发全组，只发给你上级，还是你要的吗？
> — 不是了，得让所有人都看到。

三刀砍出来：必需项是「不用我经手」和「全组可见」，「署我的名」是可弃项。真实诉求不是「自动化周报」，是「不再被逐个追问，且大家知道数据一直都在」——同一个诉求也可以靠一个所有人能自己查的看板满足，未必要发邮件。这一步的价值就在这里：**剥完之后，原方案往往不是唯一解，甚至不是最优解。**

### 三、命名并确认

把测出的东西用一句大白话说出来，交回对方确认：

> 「你要的不是『系统能导出报表』，是『不用再有人来问我数据』——导出只是手段。」

必须等他确认或修正。他修正后的措辞比你的原版更准，用他的。未经确认的命名不能作为后续依据。

### 四、反查前提

拿着确认后的核心回看原始表述，逐条列出：这个诉求成立需要哪些前提，其中哪些已经具备、哪些还缺。

对方脑内这些前提都在，表述里往往一条都没有。这份差距清单就是真正要补的工作。

## 需求清单

```text
核心诉求：（对方确认过的一句话）
落点状态：（第一步的答案；矛盾组合要拆开列）
剥离记录：（哪几刀「不是了」、哪几刀「还是」）
必需项：（砍中核心的要素——不可让步）
可弃项：（答「还是」的要素——可替换的外壳，给执行方自由度）
成立前提：（这个诉求要成立，需要先有什么）
差距清单：（每条前提 → 现状是否具备 → 缺的怎么补）
```

## 交接

清单交给执行流程时：必需项不可动，可弃项允许替换，差距清单排进实施顺序。

本技能只负责挖「他要什么」，不越界产出成品。执行侧若有自己的需求登记机制（偏好档案、铺垫清单、验收标准之类），把清单各栏对应填入即可：必需项与核心诉求进偏好类记录，差距清单进待办类记录。
