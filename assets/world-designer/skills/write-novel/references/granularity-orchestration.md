# 粒度编排协议

**适用层级**：覆盖 `L0-L7`，是全 Skill 的唯一粒度顺序权威。
**解决问题**：确定当前层级、上下游关系、跳级限制、回修路径。
**不解决**：不提供具体 meme、人物、世界观或正文技法细节。
**缺前置时**：若用户目标仍不清楚，先回看 `collaboration-and-questioning.md`；若要具体执行，再转到对应细分 reference。

本文件定义长篇网文创作的步骤顺序、粒度边界、上下游关系和跳级限制。处理复杂创作任务时优先读取本文件，再按需要读取其他 references。

条目：§G1 总原则 ｜ §G2 粒度阶梯 L0–L7 ｜ §G3 常用战术挂载点 ｜ §G4 默认调用顺序 ｜ §G5 跳级处理 ｜ §G6 输出前粒度自检

## §G1 总原则

- 任何创作任务都先判断当前所在粒度，不要直接跳到正文或章纲。
- 上一层粒度没有稳定之前，不要展开下一层细节；否则会出现设定漂亮但追读断裂、人物很满但主线无承诺、章节很多但爽点无序的问题。
- 每一层只解决本层问题，不要用低层细节弥补高层缺失。
- 如果用户直接要求低层产物，例如“写第一章”，也要先用最小篇幅补齐缺失的上层约束，再写正文。已有作品的中途章节，上层约束优先从用户的前文、设定和账本里索取，读不到就问，不要凭空发明前史。
- 可以反向修正：低层写作暴露高层问题时，先回到对应上层修补，再继续下钻。

## §G2 粒度阶梯

### L0 输入勘察：确认任务边界

**必要性**：防止 AI 在题材、篇幅、目标读者、禁区都不清楚时自由发挥。

**本层只回答**：用户要的是创意、设定、卷纲、章纲、人物、伏笔、正文、改稿还是审稿？已有素材有哪些？哪些不能动？

**输入不足时**：读取 §C（collaboration-and-questioning.md）。如果问题会影响全书方向，一次只问一个关键问题（§C2）；如果可合理假设，先声明假设再继续。

**大纲级任务时**：用户要求全书/全卷级大纲，或希望把点子展开成完整作品时，进入 §Q2 拷问模式（grilling-and-consensus.md），沿粒度阶梯逐层确认决策，共识达成前不产出完整大纲。

**完成标志**：能用一句话说清“我要交付什么、服务什么读者体验、受哪些约束”。

### L1 核心乐趣：确定读者为什么追读

**必要性**：这是全书的体验靶心。没有它，后续设定、人物、世界观会各自漂亮但互相抢戏。

**本层只回答**：读者最想持续获得什么感觉？核心爽点/痛点/期待是什么？作品的 meme、商业卖点、情绪靶心是什么？

**常用文件**：读取 §M（meme-and-commercial-funnel.md），重点 §M1–§M4 与 §M9。

**禁止下钻**：不要在本层详细编章节、技能体系、地图、势力表。

**完成标志**：能输出一句话卖点 + 核心乐趣 + 主要期待 + 主要风险。

### L2 主线承诺：确定长线问题和延迟兑现

**必要性**：长篇需要一个能拖住读者的“大问题”。没有主线承诺，章节只会变成事件串。

**本层只回答**：全书最大悬念/目标/关系承诺是什么？它让读者产生什么长期情绪欲望？为什么现在不能兑现？读者每一卷靠什么相信它最终会兑现？

**常用文件**：读取 §W4 主爆点与副爆点（standard-workflow.md）。

**禁止下钻**：不要提前写具体战斗、告白、破案细节；只确定承诺、阻碍、阶段性接近。

**完成标志**：能说明主爆点、延迟原因、阶段性副爆点和最终回收方向。

### L3 结构骨架：确定卷、阶段和节奏循环

**必要性**：把长线承诺切成可追读的阶段，避免中段塌陷。

**本层只回答**：每卷/阶段的目标、压力、误导、反转、收益、结尾新坑是什么？长期情绪如何细化成本阶段的子目标欲望？阶段之间的情绪如何承上启下、交替覆盖？

**常用文件**：读取 §W5 情绪线管理（standard-workflow.md）与 §T3 逐卷流程（planning-templates-and-review.md）。

**禁止下钻**：不要把每章写满细节；不要在世界观百科里停留。

**完成标志**：每个阶段都有“进入理由—升级压力—阶段兑现—新期待”。

### L4 系统支架：人物、伏笔、世界观服务结构

**必要性**：人物、伏笔、设定必须服务主线承诺和阶段节奏，而不是独立堆料。

**本层只回答**：谁推动冲突？谁制造误解？谁负责关系张力？哪些伏笔何时误导、何时回收？世界规则如何制造困境？

**常用文件**：读取 §N（narrative-character-worldbuilding.md）。

**禁止下钻**：不要直接写正文风格；不要把设定解释放在剧情推进之前。

**完成标志**：人物矩阵、伏笔 ledger、世界规则都能对应到具体阶段作用。

### L5 章节工程：把阶段拆成连续钩子

**必要性**：卷纲成立不等于章节可读。章节层要保证每章都有压力、变化和追读钩子。

**本层只回答**：本章目标是什么？冲突如何升级？信息差怎么变化？本章情绪从上一章继承什么、向下一章迁移什么？结尾给什么未完成期待？

**常用文件**：读取 §W2 开头 10 章组合拳与 §W6 一波三折（standard-workflow.md），必要时 §T1–§T3（planning-templates-and-review.md）。

**禁止下钻**：不要在没有章节目的时写大段正文；不要一章同时解决太多高层承诺。

**完成标志**：每章能写成“场景目的—读者期待—阻碍—转折—奖励/新坑”。

### L6 场景/正文：执行具体叙事

**必要性**：正文是兑现上层设计，不是重新发明全书方向。

**本层只回答**：当前场景用谁的视角、切成哪些镜头、制造什么情绪、推进哪条信息、改变哪段关系、留下哪个钩子？

**常用文件**：读取 §P（prose-and-formatting.md）：先过 §P7 叙事姿态与 §P8 信息喂给，再按 §P1 切镜头。涉及人物互动或战斗时，可回读 §N2 人物系统、§N3 内容编排的对应小节。

**完成标志**：正文能明确服务一个章节目的，并在结尾制造下一步阅读动力；通过 §P8 的正文姿态四问。

### L7 审稿/回修：从低层问题回溯高层原因

**必要性**：很多正文问题根源不在文笔，而在上层承诺、人物动因或节奏缺失。

**本层只回答**：问题属于核心乐趣、主线承诺、阶段节奏、人物支架、章节钩子还是文字执行？应该回到哪一层修？

**症状译码表**（从用户主诉定位疑似层级，再回对应层验证）：

| 主诉症状 | 疑似层级 |
|---|---|
| 开头没人点、前三章流失 | L1 卖点与开局漏斗（§M6–§M9） |
| 能看但不追更、弃书随缘 | L2 主线承诺缺失或主爆点无预告（§W4） |
| 中段很水、节奏塌陷、日常发飘 | L3 情绪线空窗（全线同时建立或过渡）、副爆点断供（§W5、§T5） |
| 设定漂亮但人物工具化、冲突硬凑 | L4 人物动因与伏笔支架（§N2、§N3） |
| 有剧情但章末不想翻页 | L5 章节钩子工程（§W2、§W6） |
| 画面乱、情绪平、文笔“差一口气” | L6 镜头与执行（§P1–§P5） |
| 像事件报告/流水账、说书人腔、叙述者替读者总结 | L6 叙事姿态与信息喂给（§P7、§P8）；信息倾倒反复出现时回查 L5 章纲是否漏了“本章信息块”清单 |
| 读着像 AI 写的、句式套路重复、比喻泛滥 | L6 句式与措辞（§P9） |
| 世界像布景板、场景干瘪没质感、主角总被巧合救走 | L6 场景质感与后果执行（§P10）；反派持续降智则回 L4 查动因（§N2 暗面动因） |
| 对话过完就跳走、人物凭空出现消失、场景之间不连续、读不出人在哪 | L6 场景单位与驻场（§P11）；一章场景反复超过 3 个则回 L5 查章纲节拍是否超载 |

**常用文件**：读取 §T6 自检清单（planning-templates-and-review.md），必要时按上表症状回读对应条目。

**修改护栏**：涉及破坏性修改、上下文不足的单点修改或与既有设定的事实冲突时，先走 §Q7 共识护栏（grilling-and-consensus.md），商讨确认后再动手。

**完成标志**：先定位层级，再给修改方案；不要只做句子润色。

## §G3 常用战术挂载点

当处于不同粒度时，优先调用对应战术，不要把所有技巧混在一起：

- **L0 输入勘察**：全书大纲级任务进入 §Q2 拷问式访谈；修改类任务先过 §Q7 共识护栏。
- **L1 核心乐趣**：优先用 §M1–§M3 meme 提炼与剖析、§M6 商业阅读漏斗、§M8 第一共鸣三检验、§M9 情绪靶心法。
- **L2 主线承诺**：优先用 §W4 主爆点/副爆点、欲拒还迎、封存爽点，情绪细化见 §W5。
- **L3 结构骨架**：优先用 §T3 逐卷流程、§T4–§T5 伏笔与情绪线账本的回收检查，配合 §W5 情绪承上启下与交替覆盖。
- **L4 系统支架**：优先用 §N1 前置伪装、§N2 冲突来源、§N4 三重审视与规律例外。
- **L5 章节工程**：优先用 §W2 开头 10 章组合拳、§W5 情绪承上启下、§W6 一波三折与新坑续命。
- **L6 场景 / 正文**：优先用 §P7 叙事姿态、§P8 信息喂给、§P11 场景单位与驻场、§P1 镜头化写作、§P2 反差基线、§P3–§P5 身体/战斗/情感描写、§P10 场景质感与闲笔、§P6 标点约定；成稿后过 §P9 句式扫描。
- **L7 审稿 / 回修**：优先用 §T6 自检清单，并回溯到出问题的上一层。

## §G4 默认调用顺序

### 从零规划长篇

L0 输入勘察 → L1 核心乐趣 → L2 主线承诺 → L3 结构骨架 → L4 系统支架 → L5 章节工程 → L7 自检。

任务达到全书大纲级时，L1-L4 的决策用 §Q2 拷问式访谈逐层确认，共识达成后再展开完整产出。

### 设计开头 10 章

L0 输入勘察 → L1 核心乐趣 → L2 主线承诺 → L5 章节工程 → L4 伏笔/人物校准 → L7 自检。

### 写某一章或某个场景

L0 输入勘察 → 补齐 L1/L2 的最小约束 → L5 明确本章目的 → L6 正文执行 → L7 检查钩子。

### 改稿或审稿

L0 输入勘察 → L7 定位问题层级 → 回到对应 L1-L6 修正 → 再做 L7 复检。

涉及破坏性修改、上下文不足或事实冲突时，动手前先走 §Q7 共识护栏。

### 人物或关系设计

L0 输入勘察 → L1 核心乐趣 → L2 主线承诺 → L4 人物支架 → L5 章节触发点。

### 伏笔和谜团设计

L0 输入勘察 → L2 主线承诺 → L3 阶段回收 → L4 伏笔 ledger → L5 章节埋点。

## §G5 跳级处理

- 用户要求低层输出但上层缺失：不要拒绝；先用 3-6 行补齐“临时上层假设”，再继续。
- 用户只要灵感：停在 L1，不要扩写成完整大纲，除非用户要求。
- 用户只要正文：不要输出完整设定报告；只补齐写这一段必需的最小约束。
- 用户给了大量设定但没有读者乐趣：回到 L1 重排，不要继续堆世界观。
- 用户给了人物但没有冲突：回到 L2/L4，找承诺、阻碍和关系杠杆。

## §G6 每次输出前的粒度自检

输出前默问：

1. 我现在处在哪一层粒度？
2. 上一层是否已经足够稳定？
3. 我有没有用低层细节掩盖高层缺失？
4. 当前产物是否只解决本层问题？
5. 下一层需要什么输入才能继续？
