# 世界数据交付约定

构建或修改角色、物品和场景文件前阅读本文件。构建流程入口见 [SKILL.md](../SKILL.md)。

## §D1 目录与引用

- 世界根目录必须恰好有一个 `Player-<ID>`，ID 非空，新建时默认 `Player-pc`；维护现有世界时保留原 ID。
- 多张备选角色卡存入 `预设角色/` 等普通目录，选定后将资料写入唯一玩家目录。KPC 是由主持人管理的角色，不是额外玩家。
- 所有 JSON 使用 UTF-8，允许 BOM；必须是合法 JSON，不使用注释、尾随逗号、`NaN` 或空文件。空对象写 `{}`，空列表写 `[]`。
- 背包、NPC 列表、场景物品列表使用字符串数组，只保存索引 ID 或世界根目录相对路径。NPC、物品的详细资料保存在对应索引目录。
- 物品引用支持 `key`、`存档-索引-物品/key`、`存档-索引-物品/key/物品基础信息.json`。穿戴字典的值也使用物品引用。写作时优先采用前两种形式。
- 世界内引用以世界根目录为基准，不以当前文件所在目录为基准；不使用机器绝对路径或 `../`。原文和相关资料需要收进世界目录后再引用。

## §D2 车卡模板

车卡留白只针对待填写内容，不省略目录、文件或必填字段。以下是 `Player-pc/基础信息.json` 的可解析模板：

```json
{
  "姓名": "",
  "性别": "",
  "外貌": "",
  "穿戴": {},
  "性格": "",
  "职业": "",
  "身份": "",
  "说话习惯": "",
  "原则": "",
  "喜好/厌恶": {},
  "技能": {},
  "属性": {},
  "主动技能": [],
  "状态": {
    "HP": 1, "MAXHP": 1,
    "MP": 0, "MAXMP": 0,
    "Enabled": true, "Alive": true
  },
  "buff栏": [],
  "当前位置": ""
}
```

这里的 HP/MP 是准备阶段的占位值，不是角色最终数值。把按世界规则完成建卡、写入最终数值的步骤列入 `开场说明.md` 的“主持人开场白”部分，准备完成前不进入需要角色数值的正式检定。姓名待填时使用空字符串，不填“待定”或“【姓名】”等可能被误认为已建卡的名字。

同时创建 `背包.json`（无物品时 `[]`）、`关系记忆.json`、`格式化记忆.json`、`关系图.json`、`待办与目标.json` 和 `日志.txt`。其余 JSON 按用途保留合法对象或列表；日志可以为空。固定开局填好角色档案，其他目录约定相同。

## §D3 数值的唯一归属

- HP/MAXHP、MP/MAXMP、Enabled、Alive 只写入 `状态`。采用理智规则时，SAN/MAXSAN 也只写入 `状态`，不要求其他体系添加理智字段。
- `属性` 存基础属性；可选的 `衍生属性` 存伤害加值、体格、移动等指标。没有衍生指标时可省略这个分组。
- 同一项当前数值只保存一份，不在分组之间复制，不以大小写、中英文别名另存副本。日志中的历史值、Buff 修正、技能消耗不属于当前值副本。
- 维护旧角色时，先从日志和当前回合确定有效值，再合并重复字段；冲突未查明时保留现场并报告，不猜测重置。保留独有字段不等于保留同一数值的重复副本。

## §D4 构建记录

构建自查与取舍理由保存在世界目录之外的构建记录目录，例如与世界目录并列的 `<世界名称>-构建记录/构建日志.txt`，只追加记录。世界文件不引用这些记录。世界目录内的文件会交给主持人读取，文件名不会自动形成读取隔离。

## §D5 验证边界

使用随附的 Node.js 验证器检查单玩家目录、JSON 语法、必填结构、索引引用、物品位置和角色数值归属。自定义字段可以保留；脚本不会判断剧情是否合理、检定是否完整落位或文风是否达标，仍需按构建流程完成内容自查。

## §D6 玩家可见资料与内部工作

人物与物品的普通字段可能直接显示在游戏面板，包括自创的“说明”“信息”“备注”和嵌套内容。任何普通字段都按将被玩家阅读来写；不要假定世界文件只给主持人看。

- **公开事实**：身份、物品外观、已经知道的用途、纸面实际文字等放普通字段。例如地址纸条只写其实际地址与外观，不附“文字资料 1 交付物”“凭它找到主线”“供主持人推进剧情”等用途分析。合法单位与公开规则说明可保留，如“1 张”“消耗 1 MP”。
- **运行资料**：秘密、触发条件、尚未揭示的物品用途、NPC 的获知来源与披露意愿，放 `.` 开头的隐藏键或场景台本。公开事实与秘密分开写，不能只把秘密夹在公开字段的括号或后半句。
- **构建工作**：写作计划、草稿批注、自查结论、修改理由按 §D4 留在世界外，不另建人物或物品的“说明”条目保存。车卡和开局选项放主持人开场白；已完成角色只保留当前身份，不写“玩家选择默认角色”“数值按某规则随机生成”等操作历史。

落盘前按玩家可见投影逐层检查：暂时遮住隐藏键和内部台本，只读剩下的键值。玩家能从中看到什么，就按正文的公开边界核对什么。纯括号过滤不能做保密：看内容用途，不看标点。结构验证通过后仍需做这一遍内容审查。
