# 自动世界资料触发器

目录：①用途与迁移取舍 ②文件与例子 ③条目字段 ④状态条件 ⑤检测、持续与保密 ⑥交付检查。

## ① 用途与迁移取舍

需要按近期行动、故事关键词或明确状态，自动把资料提供给主持人时，在**世界根目录**创建可选的 `世界触发器.json`。宿主机械判断并注入，无需主持人自行扫描本表、调用专用工具，也没有编辑 UI。不需要这项能力的世界不生成空壳文件。

本功能只提供主持人参考资料，**不自动执行剧情、改数值、发物品、掷骰或发布正文**。注入“进入教堂需进行理智检定”不等于已经进入教堂或检定成功；正式操作继续使用现有规则、场景台本与工具。原有检定与分支七字段及索引仍需完整落位。

转换酒馆卡／世界书时，逐条按实际用途处理：

| 原内容用途 | 处理 |
|---|---|
| 关键词关联的背景、角色行为、场景约束 | 转为本表条目，长资料引用世界内文本 |
| 好感、章节、位置、任务完成等条件 | 转为 `when` 读取当前 JSON 状态；保留行为变化与剧情后果 |
| 已有的掷骰、物品、属性操作 | 映射现有工具与数据结构，本表只提供必要提醒 |
| 用正文 XML／HTML 标签存储 HP、背包、时间，供插件解析 | 删除解析包装，使用角色与世界 JSON；保留其中独有的玩法 |
| HTML 状态栏、折叠面板、插件按钮、通用 JSON 格式修补、工具协议重复提醒 | 不搬运这些平台适配内容，交给前端、校验和公共协议 |
| 信件、日记、法庭记录等作品表现形式 | 保留叙事要求；不能因为有格式就删去 |
| STscript、宏、随机、复杂递归或插件自动化 | 不复制可执行代码；提取剧情语义转换。无法等价转换时，在世界外构建记录中说明缺口，不静默丢弃 |

不要把 `{{char}}`、`{{user}}`、酒馆深度、角色消息前缀正则、脚本或假工具回执原样填入规则。用真实稳定角色 ID、来源过滤、状态条件替代。不要新增让游玩 AI 手动执行触发扫描的提示词。

## ② 文件与例子

以下为完整合法例子，路径相对**世界根目录**；引用文件也需一起交付。`世界状态和世界规则/世界共识.json` 的 `当前地点` 只是示例自定义状态，不是新增强制接口。

```json
{
  "version": 1,
  "budgetTokens": 4000,
  "entries": [
    {
      "id": "clock-tower-lore",
      "title": "钟楼背景",
      "keywords": ["钟楼", "旧钟塔"],
      "sources": ["player", "story"],
      "file": "世界状态和世界规则/钟楼背景.md"
    },
    {
      "id": "church-silence",
      "title": "教堂禁言规则",
      "constant": true,
      "when": {
        "file": "世界状态和世界规则/世界共识.json",
        "path": ["当前地点"],
        "op": "eq",
        "value": "教堂"
      },
      "content": "教堂内禁止出声。按场景台本判定违反禁令的后果，不因玩家在行动里提到教堂就认定已经进入。",
      "priority": 100
    },
    {
      "id": "forest-night-hint",
      "keywords": ["森林"],
      "secondary": {"mode": "any", "keys": ["夜晚", "天黑"]},
      "content": "若角色实际在林中夜行，注意台本中的夜间足迹线索；未调查前不要直接揭示真相。",
      "duration": 2,
      "cooldown": 3,
      "once": false
    }
  ]
}
```

顶层只支持：`version:1`、`enabled`（默认 true）、`budgetTokens`（默认 4000，1～240000，包含注入包装的估算 tokens）、`entries` 数组。未知字段会报错，不能把酒馆原 JSON 改个文件名直接交付。文件最多 120000 字符，允许 UTF-8 BOM，不允许注释和尾随逗号。

## ③ 条目字段

| 字段 | 语义与默认值 |
|---|---|
| `id` | 必填、非空且唯一的稳定字符串；不要用 `__proto__`、`prototype`、`constructor` |
| `title` / `note` | 可选标题／作者备注；note 不注入模型 |
| `enabled` | 默认 true |
| `constant` | 默认 false；true 时跳过主关键词要求，仍受状态、轮次、预算等约束 |
| `keywords` | 普通文字关键词数组，任一命中；constant 不为 true 时必填，不支持正则或宏 |
| `secondary` | 可选 `{mode,keys}`，keys 非空；mode 为 `any`（任一存在）、`all`（全部存在）、`notAny`（全部不存在）、`notAll`（不全部存在），在主条件通过后判断 |
| `sources` | 默认 `["player","story"]`；可选公开行动 player、私密行动 private_player、公开正文 story、私密正文 private_story。私密来源必须主动选择 |
| `actorIds` | 可选稳定角色 ID 数组。限制参与匹配的玩家行动和私密 story 受众；公共 story 没有角色归属，因此设置此字段后不参与扫描。它不是全局角色存在条件，也不限制 constant |
| `scan` | 可选 `{playerRounds:1,storyMessages:1}`，各为 1～100。玩家取所选来源最近 N 个有行动的回合，同回合所有玩家行动均保留；公开／私密 story 各取最近 N 条。先过滤来源和角色，再取窗口 |
| `matchScope` | 默认 window：主词与附加词可出现在窗口内不同消息；event：必须在同一消息片段内满足。始终逐条匹配，不拼接消息制造跨边界词 |
| `caseSensitive` | 默认 false；普通文字区分大小写开关 |
| `wholeWords` | 默认 false；开启时关键词两侧不能紧邻 Unicode 字母、数字或下划线。中文通常保持关闭 |
| `when` | 可选结构化状态条件，见下节；每次请求前按最新状态检查 |
| `content` / `file` | 必须且只能提供其中一个。content 为非空正文；file 为世界内相对文本路径，原文最多 120000 字符。文件引用不自动截断，不替换变量 |
| `priority` | 默认 0；大者优先占预算，也优先获得互斥组资格 |
| `order` | 默认 0；实际注入时小者在前；与 priority 独立。并列按 id 的固定字典顺序 |
| `group` | 可选互斥组名；同一次请求只选该组一条。优先条目超预算时允许选择同组较小的条目 |
| `duration` | 默认 1：激活当轮有效。D 表示含当轮共 D 轮，后续请求无需再次命中关键词 |
| `cooldown` | 默认 0；持续结束后空过 C 轮，再允许重新激活 |
| `once` | 默认 false；true 表示本次存档仅激活一次，持续期内仍会提供 |
| `minRound` / `maxRound` | 可选允许激活和提供的游戏回合区间，含两端，从 1 开始 |

priority/order 范围为 -1000000～1000000；duration/minRound/maxRound 为 1～1000000；cooldown 为 0～1000000。不存在、不合法或二进制的引用会明确报错。文件路径不接受绝对路径、URL、反斜线、`..`、`workspace/` 机器前缀或外部资源。

## ④ 状态条件

条件叶子为 `{file,path,op,value}`。file 必须是世界内 JSON 路径；path 是逐级字段名数组（支持数组下标字符串），`[]` 表示根值。使用真实标准键，不进行别名或模糊匹配。

| op | 语义 |
|---|---|
| eq / ne | 基础值严格相等／不等，不做字符串数字转换 |
| gt / gte / lt / lte | 实际值和 value 必须是数字 |
| exists | value 为 true／false，判断字段是否存在；null 算存在 |
| in | value 为基础值数组，实际值须等于其中一个 |
| contains | 字符串包含指定字符串，或数组包含指定基础值 |

组合使用 `{"all":[条件,...]}`、`{"any":[条件,...]}`、`{"not":条件}`，每个逻辑节点只能含其中一个键。最多 16 层、256 节点。字段／文件缺失时 exists 可判断缺失，其余比较返回 false；not 仍按逻辑取反。JSON 损坏不会当成缺失，会报错。交付时所有声明引用应存在；exists:false 可用于检查已有 JSON 中尚未创建的字段。

```json
{
  "all": [
    {"file":"剧情线与进度/调查/进度.json","path":["已找到密信"],"op":"eq","value":true},
    {"file":"Player-pc/基础信息.json","path":["状态","HP"],"op":"gt","value":0}
  ]
}
```

提到“我不去钟楼”也会命中钟楼关键词。要表达角色已经到达、持有物品、完成调查等真实条件，用 when，而不是让关键词代替事实。不要用 contains 搜索整个 JSON 的序列化文本。

## ⑤ 检测、持续与保密

- 宿主在模型请求前扫描正式玩家行动与已成功发布的 story，包括预设正文；不扫描输入草稿、工具回执、思考、内部提醒、文件内容或其他注入资料。
- 一轮多次工具请求不重复计时；同条目同轮最多激活一次。新 story 或状态修改可以影响本轮下一次模型请求；已经输出的正文不会被追溯改写，也不会为了触发额外发起模型请求。
- 条目持续期间仍需通过 enabled、when、轮次限制和预算。条件暂时不成立时暂停提供；恢复时只在原持续期内恢复，不延长时长。
- 例如第 5 轮激活、duration=2、cooldown=3：第 5～6 轮有效，第 7～9 轮冷却，第 10 轮可再次激活。关键词反复出现不刷新有效期。once 的有效期结束后不再激活。
- 只有通过预算与互斥选择的条目才记为激活；超预算条目不截断、不消耗 once／冷却。它仍可能在下一次请求重新竞争预算。总上下文不足时宿主整理历史；若仍放不下则明确报错，不静默删除当前资料。
- 当前资料是请求尾部的独立 user 数据消息，不伪造 assistant 或工具调用，不写入普通对话历史。持续结束后停止自动提供，但无法让 AI 遗忘过去看到的事实；阶段性行为必须写明适用条件。
- 定义放世界 JSON；激活状态放完整存档的宿主进度，支持刷新、断线继续、完整 ZIP 导入导出与回退。不要自己把冷却计数写进世界文件。旧存档没有运行状态时从首次匹配开始。
- 条目配置发生变化会重置该条目的运行状态；保持稳定 id，避免游玩途中无意重写规则。引用正文更新不会单独重置计时；删除条目后不再提供。
- 全部资料只交给房主的主持人模型；不是任何玩家的自动获知记录。私密行动触发的秘密不得因此公开给其他人，正文继续遵守受众规则。注入不授予修改源文件的读取凭证，修改前仍需 read_file。
- 可在现有 DEBUG 事件中检查 world_trigger 的命中来源、关键词和淘汰原因；不是玩家可见事件。无需新增编辑界面。
- 本版不支持概率、加权随机、正则、递归、条目依赖、任意脚本、向量触发、动态宏或任意提示词插入位置；不要用字段伪装支持。

## ⑥ 交付检查

1. 按剧情用途迁移，移除酒馆平台补丁；在世界外构建记录中列清未能转换的语义。
2. 检查关键词不把“提及”当作“发生”；重要剧情条件使用明确状态。
3. 检查全部相对路径、真实角色 ID、私密来源和条件字段，引用内容无外部依赖。
4. 调用世界结构校验器；它与宿主和文件写入使用同一规则校验器，检查未知字段、重复 ID、路径、条件及引用文件。
5. 用近期行动／story 和状态举例验证命中与不命中；记录预算不足时可舍弃哪些资料。格式通过不代表剧情条件写对。
