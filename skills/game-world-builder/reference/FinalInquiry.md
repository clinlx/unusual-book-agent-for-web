# 最终询问（构建完成后的自我审视）

## 使用规则

- **阅读时机**：只有当全部构建/改造工作完成、`validate_game_structure.js` 验证通过之后，才允许阅读本文件。构建期间你只需要知道它存在。禁止提前阅读的原因：这些问题的价值在于用"陌生的眼睛"审视成品；带着题目去构建等于应试，构建时的盲区会原样保留到成品里。
- **静默自查，不要在对话里背题**：用户并不知道本清单的存在，突然在对话中逐题作答会非常突兀。依次对照以下问题**在内部自查**，以已写出的文件为证，不允许凭印象打勾；发现的缺口直接修进文件。对话中只做正常的构建结果汇报——至多用一两句话提及"自查后补强了什么"，不要复述问题清单，更不要输出问答体。
- **这不是严格的限制，只是一种询问和建议**：并不适用于所有模组。出于制造一个优秀世界的考虑，允许你拒绝其中的某些条目，并给出自己的理由。允许拒绝，不允许敷衍跳过或悄悄忽略。
- **自查之后**：采纳的改进落实到文件，重新运行结构验证；值得留痕的取舍按 [世界数据交付约定 §D4](./WorldDataContract.md) 记入世界目录之外的构建日志（仅追加），无需向用户逐条汇报。注意：这类构建取舍属于**超游信息**，绝不要写进 `模组.md`、剧情、NPC、`世界日志.txt` 等任何运行时主持人会读取的游戏内文件。

## 问题清单

### 1. 无人值守的厚度

这个世界的主持人是 AI，没有真人 GM 的临场补救，因此它需要比传统模组更复杂的场景通路、人物关系网与相互看法、事件触发器、隐藏信息、`.内心想法` 与动机。
——你写够了吗？NPC 是否能靠台本与人物隐藏信息运转出状态机和生活循环（作息、例行事务、被打扰时的反应），而不是站在原地等玩家上门？

### 2. 信息前置链与叙事重构

分步骤的剧本中，信息的揭示有其必要条件和充分条件，玩家不可能跳过前置条件直接知道真相——如同看了剧本的人也可能根本不认识剧本里面的人。不能忽视这种可能性。
——是否设置了条件触发器：当玩家缺少前置信息就撞进后续场景时，让主持人临时重构叙事顺序，引导回更早的场景补充前置条件？
——出现离谱情况的最终手段是否备好：如果原先的结局路径已不太可能达成，是否提醒了主持人可以拓展剧本、构思命运线、在现有文件工具允许的范围内补写场景、人物目标与分支，并同步更新索引和进度，使绕路走向结局变得可能？

### 3. 阶段门禁

对于只有剧本/故事后期才能到达的进度——危险地点、宏大事件、强大敌人——无论是出于剧情体验还是战斗难度：
——是否设置了合理的条件触发器（除非故事已进行到允许的阶段），将过早到达的玩家驱赶/打断/劝离，引导回当前阶段的正路？

### 4. 台本推演与信息闭环

一种最佳的创建方式是：结合"动态世界"的特点编写大量台本，从开局开始，按照 `模组.md` 中的内容参考，思考玩家的每一步可能性，将可能的行动和结果都推演出来，整理出一份完善的"如果-则""若…就…"触发器，作为脉络的强引导串联整个故事通向结局。对照自查：
——以信息作为导向的闭环是否成立：取得触发器信息 → 玩家自由活动 → 接触触发器 → 取得后继触发器信息 → …如此循环，引导玩家完成全流程？
——能触发每个关键信息的承载对象是否不少于 2 个，保证信息在流程中可探索、可知？
——模组中的"固定场景/人物/事件/物品特写""固定对话""固定文献"等原文，是否以触发器或物品说明的方式嵌入整个故事，确保所有情节完整出现，还原模组体验？
——时间节奏是否张弛有度：是否有故事需要一定时间回合来推进触发——定期的倒计时器舒缓节奏、某些触发器延迟得到结果、在安逸期结束前不出现异常？需要舒缓的剧情，是否做成了尽可能多个阶段相连、相互存在延迟的链状触发器；需要紧凑的，是否用少量触发器加原文？

### 5. 探索期的倒计时掷骰

到达模组规定的玩家自由探索环节，或玩家解决一个阶段性困境后：
——是否安排了基于难度范围确定骰子大小的掷骰，用于确定触发下一个触发器的倒计时，给玩家营造安逸的氛围？
——"回合延迟计时器"是否留足，防止剧情推进太快，给玩家自由探索和调整节奏的空间？

### 6. 对账与留白

——关键触发器与模组文件的对应关系是否已确认（对剧情的作用，或对应的原文行数/章节——原文应是已转写进世界目录的 md，而非外部 PDF 等文件）？可与 `世界状态和世界规则/检定与触发器索引.md` 互为对账。
——是否按照模组要求，留有对应的玩家自由活动时间？

### 7. 开场是不是一个故事的开头

玩家看到的第一屏，决定他把接下来几十回合当成一场故事还是一份设定集。逐项对照 `样例开场.md` 与 `开场白.md`：
——`样例开场.md` 里有主角吗？能不能指出至少一处呼吸、体感、视线或动作落在"你"身上？如果通篇只有物件、场景与伏笔，一段一个描述，那它不是开场，是环境巡览。
——读完开头，玩家站得住脚吗？他知道此刻正在发生什么、谁在场、利害在哪、自己为什么脱不开身吗？注意判的是**站不站得住**，不是**交代了多少设定**——几句勇者与魔王的对白就能立住一整场冲突，不必写一段大陆与纪元。
——反过来查：有没有哪一段是纯粹的设定交代，抽掉之后处境依然成立？如果有，它就是解说腔，该化进对白、动作或"你"的感受里，而不是单独立着。
——留白是不是只落在角色卡里确实待填的字段上？凡是素材已经给定的身份、履历、关系，有没有被无谓地绕开？绕开已知信息写出来的开场，读起来就像作者被绑住了手。
——`开场白.md` 有没有把"开局就定死、事后改不了"的选择都交给玩家（多开局分支、预设卡、可选规则与难度、分级开关、起始章节），并各自标了默认值？有没有哪一项是你替玩家选了、而玩家本该有权选的？
——以上任何一项不过关，回 `reference/OpeningCraft.md` 对症：场景散成巡览查 §O1，旁白在解说查 §O2，设定靠交代查 §O3，顺序不对查 §O4，满篇都是伏笔物件查 §O6，句子有机翻感查 §O7。

### 8. 终问

你当前的世界，确定能按照 `模组.md` 流畅完成各个人物、各个地点相对独立的支线流程吗？并且触发缓慢、节奏舒缓、保留足够的神秘感，最终回到主线？
——不要急着下"能"的结论。至少挑两条支线和一条主线路径，在内部推演一遍；推演中卡住的地方，就是要修的地方。
