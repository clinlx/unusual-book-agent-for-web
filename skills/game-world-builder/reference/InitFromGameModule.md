# 从模组构建世界

## 适用场景

当用户提供已有TRPG模组、COC模组、DND冒险、调查剧本、城市沙盒、线性剧本、明暗双线故事，或者要求“把这个模组转换成当前世界结构/可运行游戏世界”时，使用本 reference。

本流程的目标不是照搬模组文本，而是先备团，然后转换。把静态模组转化为动态响应的故事引擎，让主持人能够根据玩家行动自然推演，而不是强行执行固定流程。

## 开局类型：车卡开局

从模组构建的世界**默认是车卡开局**——模组与主角解耦，玩家进场先创建角色。因此：
- 产出 `模组.md`（故事大纲、章节文件索引、补充规则索引、关键判断节点、特殊机制、数据面板）——它任何开局都不能丢。
- **不产出 `故事.txt`**：没有既定主角标记，运行时便走车卡流程。
- 照常产出开场双文本（见 SKILL.md"开场双文本"）：`开场白.md` 必须含车卡引导；`样例开场.md` 只对该卡确实待填的字段留白，模组已给定的身份、背景、处境照写照用——**车卡开局不等于主角空白**。
- 唯一 Player 的 `基础信息.json` 使用完整 JSON 模板，仅待填字段留空（见 [世界数据交付约定 §D2](./WorldDataContract.md)），等运行时玩家车卡填入。
- **模组自带预设角色卡时**：卡是可选的（玩家从中挑一个）→ 仍是车卡开局，把卡收进 `预设角色/` 等普通目录，不额外创建 Player，并在 `开场白.md` 的开局配置面板里逐张列出供挑选，样例开场取各卡共同处境写足。卡是**不可替换**的既定主角（玩家必须扮演此人）→ 改走固定开局，在 `模组.md` 之外**再加** `故事.txt`、预填主角档案、另存 `开场剧情.txt`。

## 核心原则

先备团，然后转换。

备团的核心不是复述模组，而是通过编剧思维和模块化准备，将静态模组转化为动态响应的故事引擎，提升玩家沉浸感与真实自由度。

转换时必须保留模组的核心张力，但不要迷信模组的固定流程。主持人守护的是玩家能理解冲突、拼出真相、承担后果，而不是按顺序踩点。

不要花时间预先撰写大量CG，那会固化引导方向，阻碍真正响应玩家选择。需要的是欲望、资源、计划、锚点、倒计时和可替换的展示方式。

## 备团流程

### 1. 第一遍通读：建立整体印象

第一遍阅读只求建立整体印象，不急着转写文件。需要判断：

- 模组属于单线标准叙事、城市沙盒、明暗双线，还是混合结构。
- 玩家初始钩子是什么。
- 主冲突是什么，谁在推动它。
- 模组默认结局是什么。
- 玩家不介入时，世界会怎样发展。
- 哪些信息、NPC、地点、事件绝对不能丢。

第一遍结束后，应当能用几句话说清楚模组的核心张力。

### 2. 第二遍拆解：模块化分级

第二遍阅读要把模组拆成可搬运、可替换、可跳过、可重组的模块。

将大地图拆分为场景模块，并分为三个等级：

- 核心模块：与主线强相关，承载核心冲突、关键真相、最终选择或不可缺失的NPC。
- 支线模块：提供佐证信息、资源、关系变化、替代解法或补充背景。
- 氛围模块：渲染环境气氛、生活质感、恐惧感、荒诞感、压迫感或题材风味。

分级不是为了删除内容，而是让主持人可以根据玩家兴趣和时间灵活取舍节奏。

### 3. 提炼不可删的核心张力

每个预设情节都要拆成：

- 核心张力：必须保留，否则模组失去味道。
- 展示方式：可以替换，取决于玩家方案。
- 信息来源：原始锚点和备用锚点。
- 代价结构：不同选择会付出什么。
- 默认轨迹：玩家不管时会发生什么。

主持人守护的是核心张力，不是原剧本顺序。

### 4. 清点检定与分支判断（对账起点）

第二遍拆解的同时，逐场景、逐段落清点模组写明的全部检定与分支，逐条编号录入 `世界状态和世界规则/检定与触发器索引.md`（七字段与落位规则见 SKILL.md"检定与分支触发器"）：

- 属性/技能/对抗/豁免/理智检定，连同 DC 与成败后果。
- 自动触发的检定：进入即检、目击即检、周期检、阈值检——模组常用"第一个走进房间的人""每当…就"这类句式而不出现"检定"二字，这些同样要收。
- 模组既有的分支判断："如果玩家…则…"、成功/失败分岔、选择型分岔、结局条件，包括藏在 GM 提示框、NPC 对策、陷阱/机关说明里的。

这份清单是后续动态转换的对账基准：转换结束时每一条都必须有写入位置，一条"未落位"都不允许。动态转换允许替换展示方式、拆掉固定流程，但**不允许把模组既有的检定和分支判断转丢**——可替换的是"如何呈现"，不可丢的是"何时判、判什么、成败各去哪"。

## 动态转换流程

### 1. 提高冲突的最低燃点

不是等玩家到达才出事，而是让冲突在玩家到场时已一触即发。

转换每个场景时，要写清楚：

- 玩家抵达前，场景已经发生了什么。
- 玩家抵达时，哪些人正在争执、隐瞒、准备行动或濒临失控。
- 玩家在30秒内能理解的表层诉求是什么。
- 玩家做出不同选择时，谁受益、谁受损、谁记恨。

这样玩家一进入场景就被迫理解立场并做选择，角色扮演从选择开始。

### 2. 将结局状态可替代化

删掉预设结局的唯一性，只保留各势力的欲望、资源和计划，推演玩家不介入时世界的默认轨迹。

每个势力至少写明：

- 欲望：此势力真正想得到什么。
- 资源：它现在拥有什么人、物、权力、秘密、地盘或仪式条件。
- 计划：它接下来会如何行动。
- 成功状态：无人阻止时它会达成什么。
- 失败反应：计划被玩家打断后它会如何调整。

不同选择必须带来不同代价，这才是真正的自由度。

### 3. 将预设情节可拆卸

当玩家想出模组未写的方案时，核心张力必须保留，展示方式则可灵活替换。

例如获取证据的核心张力是“证据存在且被保护”，展示方式可以是潜入、贿赂、放火、社交套话、伪造身份、跟踪携带者、制造混乱等。只要玩家方案能合理触及核心张力，就应当允许它对接剧情。

### 4. 建立过程网格

用过程网格替代传统流程图。为每个势力画一条线：

- 起点：势力欲望。
- 中段：正在进行的动作步骤。
- 交集：这些步骤会与哪些地点、NPC、物品、线索产生交集。
- 终点：计划达成后的状态。

玩家不是撞上剧情点，而是干扰这些势力行动线。无论玩家从哪个节点切入，都应当碰上某条行动线的某个环节。

### 5. 加入定时炸弹

为场景植入即将到来的时限，让玩家感知时间不会停止。定时炸弹可以是：

- 某人今晚出兵。
- 仪式在三日后完成。
- 舆论在黎明前发酵。
- 病情、污染、饥荒、暴乱、搜捕持续恶化。
- NPC耐心耗尽或恐惧失控。

定时炸弹的作用是促使玩家权衡信息收集与行动推进，避免调查瘫痪。

### 6. 设置视角锚点

对每个关键信息碎片，除模组指定锚点外，再预设2到3个逻辑上也可能知晓此事的备选锚点。

锚点可以是NPC、地点、物品、日志、传闻、伤痕、账本、梦境、仪式残留、敌人误判等。当玩家错过原锚点时，可以将信息自然转移到备选锚点。

主持人守护的是玩家能拼出真相，而非按顺序收集。

## NPC转换要求

主要NPC必须提炼三个核心问题：

- 诉求（此时此刻最迫切的目标）。
- 恐惧（会导致失控的压力点）。
- 秘密（分级保密信息）。

秘密分为三级：

- 问到就说。
- 需信任或交换才说。
- 除非绝境否则不说。

分级边界应随情境偏移。当玩家展现诚意、提供利益、造成威胁、改变NPC处境，或NPC意识到局势失控时，原本需要威胁的信息可主动和盘托出。

不要把所有关键线索都设为最高保密级别，否则玩家会习惯用威逼利诱获取信息。

## 预演准备

### 空椅推演法

放三把椅子代表不同角色，用其诉求和已知信息回答“我会做什么”。不预设玩家行动，只训练反应速度。

推演时重点考虑：

- 如果玩家帮我，我会给什么。
- 如果玩家威胁我，我怕什么。
- 如果玩家揭穿我的秘密，我会震惊、否认、求饶、攻击还是逃跑。
- 如果玩家杀死或带走关键NPC，我下一步会怎么调整。

### 信息落差台账

整理“谁知道什么”和“谁以为只有自己知道”。用于判断NPC对玩家抛出新信息的反应等级。

信息落差台账应当记录：

- 信息内容。
- 知情者。
- 误以为自己独知的人。
- 信息被公开后的反应。
- 可替代锚点。

### 情感素材随笔

随手记录玩家抉择、NPC言语、误会、承诺、背叛、恐惧、恩情等细节。不必提前设计回收，在后续游戏自然浮现时让故事产生因果质感。

## 写入当前世界结构

注意自包含（SKILL.md 文件修改原则第 6 条）：交付的世界只包含目录内的文件，模组原文（PDF、网页、外部文档）不会进入最终流程，属于外部依赖，不可被世界文件直接引用。凡需要保留或引用的原文段落——固定对话、文献、场景特写、检定原文——先转写成 `.md` 收进世界目录（如 `故事集/` 或章节文件夹），再引用转写后的文件。

转换完成后，将模组内容落入当前世界目录：

- `开场白.md` 与 `样例开场.md`：两份精雕开场文本（见 SKILL.md"开场双文本"），开场白含车卡引导。
- `剧情线与进度/主线剧情.md`：模组核心冲突、默认轨迹、阶段目标、主要结局。
- `剧情线与进度/<Story_Index>/剧情.md`：核心模块、支线模块、氛围模块的事件与分支。
- `剧情线与进度/<Story_Index>/目标.json`：阶段目标、成功条件、失败条件、可替代路径。
- `世界状态和世界规则/世界规则.md`：模组规则、判定、特殊机制、题材限制。
- `世界状态和世界规则/掷骰规则.md`：模组的 DC 表、判定公式、对抗规则，以及自动检定的触发时机。
- `世界状态和世界规则/检定与触发器索引.md`：备团第 4 步的对账清单，逐条标注写入位置，不留"未落位"。
- `世界状态和世界规则/世界共识.json`：公开传闻、倒计时、通缉、势力动向。
- `存档-索引-NPC/<NPC_Index>/`：NPC诉求、恐惧、秘密、关系、下一步行动。
- `存档-世界/<Region>/<Scene>/`：场景状态、燃点、事件台本、NPC和物品。
- `存档-索引-物品/<Item_Index>/`：证据、道具、资源、仪式物、钥匙线索。

## 完成标准

完成后检查以下内容：

- 是否先备团，再转换。
- 是否完成第一遍通读和第二遍拆解分级。
- 是否区分核心模块、支线模块、氛围模块。
- 是否把静态剧本转化为能响应玩家行动的动态系统。
- 是否提高每个关键场景的最低燃点。
- 是否将结局状态可替代化。
- 是否将预设情节拆成核心张力与展示方式。
- 是否为势力建立过程网格。
- 是否加入定时炸弹。
- 是否为关键信息设置视角锚点与备选锚点。
- 是否为主要NPC写明诉求、恐惧、秘密。
- 是否已逐场景清点模组的属性/技能检定、自动触发检定与既有分支判断，录入 `检定与触发器索引.md`，且每一条都已落位（场景台本/世界共识/剧情与目标/掷骰规则）。
- 自动触发的检定是否写明了触发时机与"无需玩家宣言"。
- 是否产出精雕的 `开场白.md`（含车卡引导；素材有多开局分支、可选规则或预设卡时，是否含开局配置面板）与 `样例开场.md`（处境、"你"是谁、"你"的身体与动作三样是否立住，世界观是否由处境带出而非专段交代，留白是否只落在确实待填的字段上），并在 `模组.md` 中索引。
- 世界文件是否全部自包含：未引用 PDF 等外部依赖，需要的模组原文已转写为目录内的 md 并以其为引用对象。
- 是否避免预先撰写大量CG导致固化引导方向。
- **是否已运行 `validate_game_structure.js` 验证目录结构，并修复所有报错直至验证通过。**
- **验证通过后，是否已按 SKILL.md"最终询问"阅读 `reference/FinalInquiry.md` 并逐条静默自查（此前禁止阅读该文件；条目可有理由地拒绝，不可敷衍跳过；不在对话中逐题作答）。**
