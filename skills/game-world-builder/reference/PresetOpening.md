# 预设开局约定

这三种机制可同时使用，也可只使用其中一项。文件位于世界根目录。
若用户无主动要求，不建议为世界生成预设。未提供时保持原有开局流程。

## 开局内部说明.md

放置开场前 AI 需要知道的幕后情况、准备事项或叙事安排。作为普通 user 消息放在游戏历史最前面，只有 AI 与房主调试模式可见，不写进系统提示词，不发送到玩家或观战客户端。它可以随历史被压缩、遗忘；长期必须保留的事实仍需写在世界文件、状态或摘要里。

## 预设第一回合.md

非空时，玩家完成角色选择、点击「开始故事」，且开放槽位玩家均已加入后，应用通过真正的 `append_story` 和 `end_the_round` 执行并保存第 1 回合，不调用模型。剧情、回合编号、多人同步、导出与回退均使用正常流程。下一次玩家行动是第 2 回合。

一般是作为KP的开场自述和详细开场白。有时候也会要求是小说化的开头剧情。

内容是所有玩家与观众均可见的完整公开正文，支持正常 Markdown。不会展开模板变量或依角色、人数选择分支。因此必须适配所有允许的角色选择和人数，不出现仅某张角色卡成立的身份与秘密；涉及未确定信息时，用自然的公共场景和必要的开局配置说明引导填写。不要放 `【姓名】` 等待替换符、主持指令、工具代码、幕后真相或多个待选版本。

此机制只省去固定开场的生成，不自动车卡或变更世界数据。阶段暂为「游戏前准备」。首次真正执行 AI 回合时，仍检查 PC／AIPC／KPC、处理房主保存的 NPC 要求及未完成的准备，接续现有故事，不再次发布预设开场。需要掷骰或动态分支才能决定开场时，应采用原 AI 开局流程。

文本文件每份最多 120000 字符。空的预设正文不会跳过 AI；交付时应删除不用的空文件。旧的开场说明、样例与原文不会被自动认作预设第一回合。

## 开局预读.json

```json
{
  "version": 1,
  "files": [
    "世界状态和世界规则/世界规则.md",
    "存档-世界/车站/场景信息.json"
  ]
}
```

示例路径必须换成世界内真实存在的文本文件。最多 100 个路径；相对世界根目录，或使用 `/workspace/` 前缀。不支持网址、通配符、目录、`..`、外部资源或二进制文件。不要用设计器中暂存世界文件夹的名字作前缀。

这些路径追加到默认预读的模组入口及全部启用 PC／AIPC 基础信息、背包后，自动去重(也就是无需包含`模组.md`和玩家信息与背包文件，因为这些已默认包含)；关闭角色不参加默认预读。额外清单应只列开局必要资料，避免列入关闭角色。工具回执包含真实读取结果，单次批量最多 20 个文件，单文件最多 16000 字符、整组最多 64000 字符；超长文件的截断标记与后续 offset 读取规则保持不变。

存在预设正文时，预读延后到首次实际 AI 请求前，读取当时的角色配置与文件内容。没有预设正文时，在正常开局请求前读取。无效配置、越界或缺失文件会阻止开始，需先修复；中断后恢复已生成的回执，不重复注入。回退至未开始状态后允许重新开始。

## 交付检查

运行世界结构校验；确认正文无剧透且适配可选角色／人数，所有预读文件真实存在。没有这些文件的旧世界不受影响，不要为了使用新机制而复制不合适的旧样例开场。
