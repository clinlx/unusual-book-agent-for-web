# game-world-builder 使用指南

## 它做什么

`game-world-builder` 让 AI 扮演"世界架构师"，把你的想法、TRPG 模组或小说原文，建成一套落在文件夹里的可运行游戏世界：剧情线、目标、NPC 档案、场景、物品、世界规则和状态机，全部落地为约定好的目录结构，供 AI 主持人在跑团时动态读取。

它**不会**在跑团进行中使用——它只在"主持人不处于游戏流程时"离线建造和改造世界，是后台的营造司而不是台前的主持人。它也**不会**把剧情写成固定剧本：它写的是各方势力的欲望、计划和"玩家不介入时世界的默认轨迹"，让玩家怎么乱玩世界都有响应，而不是被推回唯一路线。

## 何时使用

这是独立的技能目录。把本目录的 `SKILL.md` 提供给 AI，并指定素材和目标世界目录即可；参考文档与验证脚本随目录分发，不依赖其他技能或固定安装位置。宿主支持技能安装时，按宿主的方式安装和调用。

四种场景该用它：只有几个关键词或爽点想法（从描述构建）、手头有现成 TRPG 模组（从模组构建）、想把小说改成跑团世界（从故事构建）、以及给已有世界加 NPC/支线/修规则（改进现有世界）。角色卡输入需先提取成可读文本或结构化摘要，包含人物、背景、开场与必须保留的要素，再按素材选择构建流程。它的交付物是世界文件目录。

## 它会先决定开局类型

`模组.md`（故事大纲、章节文件索引、补充规则索引、关键判断节点、特殊机制、数据面板）是任何开局都必须有的通用引导文件，它不会丢。建世界前它判断该建成哪种开局：模组（与主角解耦）→ 车卡开局，玩家进场自建角色，只有 `模组.md`；小说/既定主角 → 固定开局，在 `模组.md` 之外**多加**一个 `故事.txt`（+ 预填主角 + `开场剧情.txt`）。运行时主持人靠"有没有 `故事.txt`"来判开局——有就跳过车卡用既定主角。从描述构建且看不出你想要哪种时，它会直接问你"扮演既定主角还是自建角色"。

## 它会先解构欲望再动手

建世界前它先做一次"欲望解构"（方法论在 `reference/DesireAndTextureCraft.md`）：不总结剧情发生了什么，而是识别**哪种欲望在驱动上瘾**（支配/占有/羞耻/堕落/反杀/背德…），拆出触发机制，再把欲望落进 NPC 欲望字段、势力目标、场景台本和阶段设计，让核心爽点在每章换着花样反复触发。作为离线营造司，它对黑暗、露骨、非常规题材不净化不回避——那些往往是作品不可修改的核心。

## 世界是一套文件状态机

它的中心思想：**目录结构就是世界的持久状态**。NPC 的记忆、场景的日志、物品的位置、世界共识里的倒计时，各自存在独立文件里，用相对路径互相引用——这既是给 AI 主持人的**注意力管理**（该看什么时候看什么，避免信息过载），也让世界可以被"存档"和演化。需要对玩家隐藏的信息用 `.` 开头的 JSON 键（如 `.内心想法`）藏起来；每条关键线索至少有两条发现路径，玩家跳过一处也拼得出真相。

修改文件时它遵守一套保守原则：能移动就不删除、先读后写防覆盖、超过 200 行就拆分、独有字段一律保留。你的世界特色（灵力、修为、污染值）不会被"套模板"抹掉。

## 它正常工作的迹象

- 建完世界后主动运行 `validate_game_structure.js`，并反复修复报错直到通过。
- 输出一份 `模组.md` 引导文件：简介、章节目录、文件索引和"故事该从哪里开始"。
- 交付两份精雕开场文本：`开场白.md`（主持人可照读的开场发言，车卡开局含车卡引导）与 `样例开场.md`（小说风格样例开场，兼作全程文风范本）。任何开局都有，缺了验证脚本会报错。
- 源材料里的属性检定、自动触发检定（进入即检、目击即检等）和剧情分支判断被逐条登记进 `世界状态和世界规则/检定与触发器索引.md`，并落位成场景台本/世界共识/剧情目标里的触发器，而不是只留在剧情散文里。
- 写出的剧情包含默认轨迹与失败分支，而不是只有"玩家应该去哪"。
- 结构验证通过后，它会打开 `reference/FinalInquiry.md`（最终询问）逐条静默自查，把发现的缺口直接修进文件——这份问题清单在构建期间被刻意禁止阅读，保证审视用的是"陌生的眼睛"；清单是建议不是硬性限制，不适用的条目它会把取舍理由记进世界目录之外的构建记录（不交给主持人，也不从游戏文件引用）。它不会在对话里向你背诵这份清单，最多一两句话提到自查后补了什么。
- 建出的世界完全自包含：不引用 PDF 模组原文等外部文件，需要的原文会转写成目录内的 md 再引用。

## 目录和数据要求

交付目录根部只允许一个 `Player-*`。车卡时保留完整 JSON 模板，仅待填内容留空；预设角色收进普通目录。HP/MP 等当前值只放在 `状态`，同一数值不存多份。具体模板、引用写法与验证边界见 [世界数据交付约定](reference/WorldDataContract.md)。

## 运行验证

需要 Node.js 18 或更新版本，无第三方依赖。把以下占位文字替换为实际路径：

```text
node "技能目录/scripts/validate_game_structure.js" "世界目录"
```

相对世界路径按命令工作目录解析；省略时验证工作目录本身。退出码 `0` 为通过、`1` 为世界结构问题、`2` 为调用参数错误。脚本维护者可执行回归测试：

```text
node --test "技能目录/scripts/test_validate_game_structure.js"
```
