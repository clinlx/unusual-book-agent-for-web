# 自检清单

## 解析自检

- 是否正确区分普通图片和图片角色卡。
- 是否保存 `raw-card.json`。
- 是否生成 `normalized-card.json`（世界书含 `category/title/plain_preview`）。
- 是否报告 base64、zlib 或编码失败原因。
- 是否提取世界书，而不是只看 `description`。
- `extraction-report.md` 是否含：字段缺口、内容复核标记、分类统计、must_land、运行协议候选、extensions 与迁移待处理字段。
- 是否把默认输出、验证样例和批量解析结果写入工作区 `/tmp/tavern-card-loader/` 或显式指定的世界外素材目录，而不是 Skill 目录。

## 内容自检

- 是否识别 `{user}`、`{{user}}`、`<user>` 并按玩家名语义理解。
- 是否没有主动替换玩家占位符。
- 是否识别 `{{char}}` 和 `<START>`。
- 是否把 HTML/CSS、宏和运行标记作为运行信息处理（`runtime_protocol`）。
- 是否标记疑似广告、下载站说明、模型宣传语。
- 是否识别数据面板、状态栏、缓存、临时变量、回合记录、背包栏和属性栏。
- 是否识别 HTML 开局页 **或** 文本表「初始地点/初始道具」，没有当噪声丢弃。
- 是否发现占位/玩笑 `first_mes` 并改用 description + start_rules。

## game-world-builder 自检

- 是否生成角色、世界观、规则、场景、物品、剧情燃点和主持提示。
- 是否把世界书条目映射到稳定事实、地点、组织、物品或规则。
- report 的 must_land 是否逐条对账到写入位置。
- 是否判断数据面板内容更适合 `NEXT_TURN_CACHE`、玩家 `背包.json`、玩家 `基础信息.json`、世界规则还是 `模组.md`。
- 是否在不理解缓存逻辑时原样保留 `NEXT_TURN_CACHE` 字符串，并把缓存内容和触发逻辑解释给主持人。
- 是否把开局引导转写为 `模组.md` 车卡/开局指南，条目与原面板或文本表一一对应，不遗漏也不虚构。
- 是否保留冲突和不确定点供用户复核。
- 是否没有直接生成 game-world-builder 世界目录。

## 本地化自检

- 是否保留原卡文化事实。
- 是否避免机器翻译腔。
- 是否清理无意义外文残片。
- 是否保持译名和称呼稳定。

## 本项目的浏览器适配

以本技能 SKILL.md 的 parse_tavern_card 流程为准，不运行 Python。当前只解析 PNG 与 JSON。所有原字段、世界书设置、禁用条目与扩展均保留在 raw-card.json；分类、内容标记和 must_land 仅供复核，不是过滤依据。未知脚本不执行、不声称已转换；纯平台格式补丁无需搬运。
