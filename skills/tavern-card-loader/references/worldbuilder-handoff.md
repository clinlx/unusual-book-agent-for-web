# game-world-builder 交接参考

## 交接原则

`tavern-card-loader` 只生成摘要包。最终世界目录由 game-world-builder 创建和校验。

不直接生成 game-world-builder 世界目录。

把 `worldbuilder-brief.md` 交给 game-world-builder 时，应明确它来自角色卡，仍需要复核事实、时间线、特殊标记和世界书优先级。

## 映射到 game-world-builder

- 主卡角色：按用户意图放入 Player、KPC 或核心 NPC。
- 世界稳定事实：写入世界规则、世界共识或对应场景说明。
- 地点条目：转换为 `存档-世界/<Region>/<Scene>/`。
- 组织条目：转换为组织说明、关系图或世界共识。
- 物品条目：转换为 `存档-索引-物品/`。
- 关系动态：转换为关系记忆、格式化记忆或角色档案。
- 开场：转换为 `模组.md` 开局引导或剧情线起点。
- HTML 开局引导页面：转换为 `模组.md` 车卡指南。
- 备用开场：转换为可选开局或分支剧情。
- 规则机制：转换为世界规则、掷骰规则或主持台本。

## 数据面板与缓存交接

角色卡中出现“数据面板”“状态栏”“缓存”“临时变量”“回合记录”“背包栏”“属性栏”时，先判断它服务于哪种 game-world-builder 记忆，而不是整体搬进剧情正文。

- 回合缓存：下一回合需要恢复的短期状态、临时变量、行动队列、倒计时和本回合结算，由游玩流程工具 `end_the_round` 的 `NEXT_TURN_CACHE` 参数承载。主持人提交更新后的状态对象，宿主在成功结束回合时持久化。直接在 `模组.md` 定义所需字段的名称、类型、含义、初始值、更新及保留／清理条件，告知主持人调用流程工具时遵守；不把缓存字段写入角色信息或背包，不生成同名文件。
- 玩家背包：道具、装备、金钱、材料、资源和库存，优先交给玩家文件夹下的 `背包.json`。
- 玩家基础信息：身份、属性、等级、身体状态、阵营、称号、长期标记，优先交给玩家文件夹下的 `基础信息.json`。
- 世界规则：状态面板的刷新规则、计算公式、回合制规则、资源消耗规则，优先交给世界规则或 `模组.md` 的主持说明。
- 平台适配：只用于酒馆展示、标签解析或通用格式修补的部分不写入最终世界；独有玩法与叙事要求拆出后保留。

不确定字段的剧情语义时，在世界外交接材料中保留原值并记录待复核点。已确定属于回合缓存的数据，只在 `模组.md` 说明参数字段与更新规则，不让主持人在角色信息、背包和缓存之间随意选择存放位置。

## 开局引导页面与车卡指南交接

角色卡内置 HTML 开局引导页面（车卡界面）时，该页面映射为 `模组.md` 中的车卡指南，而不是剧情开场正文。

车卡指南的目标是教 AI 主持人如何进行车卡：

- 需要玩家填写哪些属性（对应原页面的每个输入框）。
- 需要玩家选择哪些属性（对应原页面的每组选项，逐项列出可选值和效果）。
- 有哪几种开局可供选择（对应原页面的开局入口，说明进入条件和初始差异）。
- 车卡完成后初始状态如何落地：角色事实和实际物品按数据约定保存；回合缓存字段、初始值和提交时机在 `模组.md` 定义，由主持人通过 `end_the_round.NEXT_TURN_CACHE` 提交。

指南条目必须与原初始引导面板一一对应：不遗漏原面板的填写项、选项和开局分支，也不虚构原面板没有的内容。识别方式和转写细节见 `references/field-mapping.md` 的“HTML 开局引导页面”一节。

## 使用摘要包

1. 先读 `extraction-report.md`，确认解析是否可信，并抄下「必须落地机制条目」「R18 硬性保留」「运行协议」「extensions」。
2. 再读 `normalized-card.json`：`persona.description` + 带 `category/title` 的世界书是主事实源。
3. 用 `worldbuilder-brief.md` 作分类摘要入口；**不要**把运行协议 HTML 整页当世界事实，也**不要**只靠 brief 跳过 normalized。
4. 落盘顺序建议：世界法则/防作弊 → 开局地点与初始道具 → 数据面板字段 → 遭遇/NPC 生成 → 地点日常 → 角色档案；运行协议先拆分：纯平台补丁无需搬运，剧情语义按用途落位。
5. 如果目标语言不同，结合 `localize-draft.md` 和 `references/localize.md`。
6. 构建世界后运行 game-world-builder 自身验证流程，并用 report 的 must_land 清单对账：每条都有写入位置。
