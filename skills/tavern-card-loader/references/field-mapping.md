# 字段映射参考

## 基本原则

不要机械搬运字段名。把酒馆卡内容按主持和 game-world-builder 的使用场景重组为角色、世界、规则、场景、物品、剧情线和主持提示。

## 映射表

| 酒馆字段 | 理解方式 | game-world-builder 用途 |
| --- | --- | --- |
| `name` | 主卡角色名 | Player/KPC/NPC 名称 |
| `description` | 外貌、身份、背景、关系 | 角色档案、NPC 描述 |
| `personality` | 行为模式、价值观、语气 | 角色行为规则、关系记忆 |
| `scenario` | 初始局势、世界背景 | 模组开局、世界状态 |
| `first_mes` | 开场场景 | `模组.md` 或剧情线开场 |
| `alternate_greetings` | 备用开场 | 可选开局、分支剧情 |
| `mes_example` | 语气和互动示例 | 角色口吻参考，不直接当事实 |
| `creator_notes` | 作者说明、玩法提示 | 主持提示、噪声复核 |
| `system_prompt` | 行为约束 | 世界规则或主持规则 |
| `post_history_instructions` | 后续回复约束 | 长期主持规则 |
| `character_book.entries` | 世界书 | 地点、组织、规则、NPC、物品、时间线 |
| `tags` | 类型、语言、题材 | 分类与风险提示 |
| `extensions` | 酒馆扩展信息 | 运行信息，通常不写成世界事实 |

## 数据面板与缓存字段

部分角色卡会把数据面板、状态栏、缓存、临时变量、回合记录、背包栏、装备栏、属性栏写在 `description`、`scenario`、`system_prompt`、`post_history_instructions`、世界书或示例提示里。遇到这类内容时，不要简单当作普通剧情文本，也不要擅自删除。

优先按用途判断落点：

- 临时回合状态、下一回合提示、短期行动队列：通过游玩流程工具 `end_the_round` 的 `NEXT_TURN_CACHE` 参数更新并持久化。直接在 `模组.md` 定义所需缓存字段的名称、类型、含义、初始值、更新及保留／清理条件，告知 AI 主持人按定义提交；不要把缓存字段写进角色信息或背包。
- 玩家持有物、装备、道具栏、金钱、资源、库存：优先映射到玩家文件夹下的 `背包.json`。
- 玩家属性、身份、等级、数值、身体状态、阵营、称号、长期标记：优先映射到玩家文件夹下的 `基础信息.json`。
- 长期世界机制、状态面板计算规则、回合刷新规则：优先映射到世界规则或 `模组.md` 的主持规则。
- 仅用于酒馆展示或插件解析的 UI、标签与格式补丁：原始提取包保留供复核，最终世界无需搬运；其中独有玩法或叙事形式须另行保留。

如果同一数据面板同时包含回合缓存、玩家物品和玩家属性，应拆分理解：缓存的字段定义与更新规则写在 `模组.md`，运行时由主持人提交到 `end_the_round.NEXT_TURN_CACHE`；实际物品进 `背包.json`，角色当前身份或属性进 `基础信息.json`。`NEXT_TURN_CACHE` 是参数中的状态对象，不是独立工具或同名文件，不把整份缓存复制进人物档案或背包。

## HTML 开局引导页面（车卡界面）

部分角色卡会在 `first_mes`、`alternate_greetings`、`scenario`、世界书或正则/脚本扩展里内置 HTML 编写的开局引导页面，带有输入框、下拉选择、单选/多选、按钮等交互元素，用于让玩家车卡（创建角色）和选择开局。

识别特征：大段 HTML 中出现 `<input>`、`<select>`、`<option>`、`<button>`、`<form>`、`type="radio"`、`type="checkbox"` 等表单元素，或明显的“确认开始”“选择开局”“角色创建”交互结构。

处理方式：

- 不把整段 HTML 当作普通运行噪声丢弃，也不原样贴进剧情正文。
- 转写为 `模组.md` 中的车卡指南。指南面向 AI 主持人，说明开局前如何带玩家完成车卡。
- 车卡指南条目与原引导面板一一对应：
  - 每个输入框对应“需要玩家填写的属性”，注明字段名、含义、默认值和格式限制。
  - 每组选项对应“需要玩家选择的属性”，逐项列出可选值及各自效果。
  - 每个开局入口对应“可选开局”，说明有哪几种开局、各自的进入条件和初始差异。
  - 页面中的提交/生成逻辑对应“车卡完成后如何生成初始状态”：角色事实与实际物品按数据约定落盘；回合缓存只在 `模组.md` 定义字段与初始值，告知主持人通过 `end_the_round.NEXT_TURN_CACHE` 提交。
- 不遗漏原面板的任何填写项或选项，也不虚构原面板没有的选项。
- HTML 标签、CSS 样式和脚本实现本身仍按运行信息记录，不写入世界事实。
- 无法完全理解交互逻辑时，原样保留关键 HTML 片段或字段名，并在车卡指南中提醒主持人复核。

## 文本表开局 / 初始道具（非 HTML）

部分卡不用表单，而在世界书写「初始地点选择 → 背包初始道具」对照表（如：自己的家 / 学校 / 放学路上 / 公共厕所）。脚本会把这类条目标为 `start_rules`。

处理方式：

- 每个地点 = 一个可选开局或场景入口。
- 每个地点的道具列表写入对应开局的 `Player-*/背包.json` 或物品索引，并在开场文本中提及。
- 不得因为没有 `<input>` 就当成普通 lore 忽略。

## 世界书自动分类（脚本产出）

`normalized-card.json` 的世界书条目含：

- `title`：comment/name，或从正文/`【】`/`name="Protocol"` 启发式生成
- `category`：`world_rules` / `start_rules` / `data_panel` / `encounter_rules` / `locations` / `runtime_protocol` / `lore`
- `plain_preview`：去 HTML 预览

分类只用于复核，不能自动删正文。纯平台补丁不搬运；混合条目先拆出剧情与玩法。常驻且空关键词不代表噪声。本版不单独自动判定 r18_mechanics，内容原文仍保留。

## 复核重点

- 示例对话展示语气，不等同于已经发生的正史。
- 作者说明可能混有广告、鸣谢、模型建议，要标为疑似噪声。
- 世界书条目如果写的是规则、地点、组织或物品，应优先交给 game-world-builder。
- 数据面板和缓存字段要按用途拆分；不确定时原样保留关键字符串，并在交接材料中提醒主持人复核。
- 剧情事实冲突时保留原值并报告，不机械认定世界书或 system_prompt 永远优先；V2/V3 以 data 镜像为规范化主数据，并列明冲突。
