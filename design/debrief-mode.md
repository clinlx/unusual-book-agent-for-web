# 故事结束后的主持人复盘

## 模式与入口

故事完整结束后，房主可以在铭刻角色旁开启复盘。确认框说明可能产生 token 消耗、转换不可逆、之后不能回溯。多人房间整体进入同一复盘会话，使用房主的模型配置。

`save.debrief` 是不可逆的模式标记。游戏的 `status` 继续为 `ended`，回合数不变。历史剧情、世界文件、角色状态和原快照均保留；游戏推进、回溯、游戏上下文重建在命令入口和核心层同时拒绝。原有游玩提示词不修改。

开启后隐藏复盘入口，保留故事结尾的铭刻按钮。尚未铭刻的玩家还会在原回溯位置得到第二个铭刻入口，两者调用同一操作。铭刻成功后保留原入口的“已铭刻”状态，侧栏恢复禁用的回溯按钮。

复盘记录显示在故事之后，可整体折叠；折叠状态按存档保存在本机，不影响其他玩家，也不删除上下文。输入框始终可用，包括角色死亡、无意识以及 AI 正在回答期间；客户端掉线时不能发送。观战者保持只读，观战房主可参与讨论。

## 主持人请求

复盘使用独立的系统提示词与模型消息列表，不继承旧主持人流程指令、世界书自动触发器或游戏工具回执。首次自动简短介绍主持人身份，后续优先直接回答；需要核实事实时查询历史。工具仅提供 `read_file`、`list_dir`、字面关键词 `search`，执行器独立于游戏工具，不允许文件修改、剧情发布、掷骰或回合推进。

单人可以只读查询世界目录和历史归档。共享房间只暴露公共历史投影，不暴露其他玩家的私密行动、隐藏缓存或原始工具记录；公开复盘的回答会被全房间看到。这个限制在文件提供层执行，不依赖模型自律。曾经共享的复盘导出后仍保持此限制。

系统提示词交代 `/workspace/过往回合历史记忆`、`/workspace/SummaryHistory.json`、`/workspace/复盘记录` 的用途和分段读取方法。初始请求携带结局附近的公开剧情；较远历史按需读取。最近少量复盘对话保留在请求中，过长输入转成带消息 ID 的资料索引。旧查询结果可缩短或重新读取，原始游戏记录和复盘发言不删除。

文件内容按需生成，不复制整个工作区；单次读取最多 12000 字，搜索限制文件数、字符量和返回条数。请求预算预留模型输出和工具定义；连续工具查询有上限，耗尽后进入可继续的中断状态。

## 消息队列

房主是唯一计时与批次分配者。复盘不使用游戏行动收集表，不等待所有玩家发言，也不支持隐秘、伪装或空过。

| 状态 | 收到公开发言后的行为 |
| --- | --- |
| waiting | 发言成为独立公共气泡，ID 加入 pending，dueAt 重设为当前时间加 5000 ms |
| running | 发言进入 queued，仅发送者可见，允许本人撤回 |
| interrupted | 新发言继续暂存，等待房主继续 |

计时结束后冻结 pending 为 active 批次。AI 收到按顺序排列的 `speaker_id`、`speaker_name`、`content` 列表；身份由房主从成员绑定和角色资料填写，客户端只能提交正文。同一玩家可以多次发言。请求 ID 用于重传幂等，重复请求不再次延长计时。

AI 完成回答后，先保存主持人气泡，再把 queued 的发言依次公开、移入 pending，重新开始 5 秒合并窗口。房间始终只有一个复盘请求在运行。队列最多暂存 200 条，单条最多 20000 字，超出时明确拒绝而非丢弃已有消息。

## 保存与恢复

复盘保存于存档元数据中，与原游戏消息和事件分开：`events` 是已提交的讨论，`pending` 是待合并 ID，`queued` 是预定发言，`active` 保存本批输入 ID、已完成的只读工具批次和完整待提交回答。

每次接受发言及批次转换均通过房主串行事务保存。自动失败重试复用既有设置，默认关闭；只重试模型请求。最终失败保留当前批次和预定队列，显示“继续复盘”。刷新不会悄悄重发运行中的请求，而是把它转为中断；已经完成的只读工具结果可接着使用。保存失败不会启动无休止的自动请求。

完整 ZIP 导出与导入保留模式和队列。故事 HTML 导出包含独立、可折叠的复盘附录，只收录已提交发言和完整回答，不收录预定发言、思考内容或工具回执。附录不计入游戏演绎节点；演绎到结尾或切换总览后可查看。
